# NoteCore v0.2.0

NoteCore devient un carnet qui fait **réviser** ce qu'on y écrit, avec une
interface entièrement redessinée, une personnalisation poussée du texte et de
vrais programmes d'installation pour Windows et Linux.

## Contenu

### Réviser ses notes

Les cartes de révision s'écrivent **dans la note**, en Markdown :

| Syntaxe | Effet |
| --- | --- |
| `{{c1::mot caché}}` | Cache le passage ; les trous de même numéro sont révisés ensemble |
| `{{c1::mot::indice}}` | Idem, avec un indice affiché à la place |
| `Question :: Réponse` | Une ligne = une carte |

Aucune seconde copie à synchroniser : la base ne garde que l'état
d'apprentissage. La planification est calculée localement par l'algorithme
**FSRS v6**. Séance en plein écran au clavier (`Espace`, `1`–`4`, `Z` pour
annuler), série de jours, activité sur 14 jours et maîtrise par dossier et par
étiquette sur l'accueil. Retirer une carte du texte la met de côté 30 jours
plutôt que de la détruire.

### Nouvelle interface

Accueil, palette de commandes (`Ctrl/Cmd+K`), paramètres par onglets, modes
Éditer / Scinder / Aperçu, mode concentration (`Ctrl/Cmd+\`), liste des notes
groupée par période, thèmes clair et sombre repensés. Un **guide de prise en
main** s'ouvre au premier lancement (et se rouvre depuis les paramètres).

### Personnalisation

23 polices embarquées (interface, texte, titres, code), taille, interligne,
graisse, largeur, couleur d'accent, densité, six préréglages. Réglages
locaux : le Markdown des notes n'est jamais modifié.

### Installation

- **Windows** : installateur sans droits administrateur, en français, avec
  désinstallateur ; exécutable autonome toujours disponible.
- **Linux** : paquet `.deb` (Debian, Ubuntu 22.04+), archive `.tar.gz` avec
  `install.sh` (sans `sudo`), et `PKGBUILD` pour Arch (voir le README).

### Corrections

- Export : les pièces jointes de deux notes de même titre ne s'écrasent plus ;
  en-tête YAML toujours valide ; le manifeste nomme les dossiers.
- Recherche par préfixe (« arch » trouve « architecture »).
- Épingler une note ne modifie plus sa date de modification.
- Les liens s'ouvrent dans le navigateur du système au lieu de remplacer la
  fenêtre de l'application.
- `Ctrl+Z` fonctionne, y compris après une action de la barre d'outils.
- Plus de mise à jour perdue lors de sauvegardes automatiques rapprochées.
- Moteur Markdown : listes imbriquées, tableaux, citations riches, code protégé.

## Mise à niveau

Installer cette version **conserve vos notes**. Le schéma de la base passe en
version 3 (cartes de révision) : une copie de la base d'avant est écrite à côté
(`notecore.db.avant-migration-<date>`) avant la migration, et son chemin est
affiché au lancement. Les notes qui contiennent déjà `::` sont analysées une
fois pour en tirer d'éventuelles cartes.

## Fichiers

Les empreintes SHA-256 de chaque fichier sont dans `SHA256SUMS`.

| Fichier | Pour |
| --- | --- |
| `notecore-v0.2.0-windows-x64-setup.exe` | Windows 10 / 11, installateur (recommandé) |
| `notecore-v0.2.0-windows-x64.exe` | Windows 10 / 11, exécutable autonome |
| `notecore-v0.2.0-linux-amd64.deb` | Debian, Ubuntu et dérivés |
| `notecore-v0.2.0-linux-x64.tar.gz` | Toutes distributions (`./install.sh`) |
| `SHA256SUMS` | Empreintes |

Vérifier un téléchargement :

```
sha256sum -c SHA256SUMS --ignore-missing
# ou, sous Windows :
Get-FileHash notecore-v0.2.0-windows-x64-setup.exe -Algorithm SHA256
```

## À savoir

- Les exécutables ne sont pas signés numériquement : Windows SmartScreen peut
  afficher « Windows a protégé votre ordinateur » ; choisir **Informations
  complémentaires** puis **Exécuter quand même** après avoir vérifié
  l'empreinte.
- NoteCore a besoin du runtime WebView2 sous Windows (installé au besoin par
  l'installateur) et de WebKitGTK 4.1 + GTK 3 sous Linux.
- Le projet n'est pas publié sur l'AUR ; sous Arch, construire le paquet avec
  `makepkg -si` dans `packaging/aur` (voir le README).
